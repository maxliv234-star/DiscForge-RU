# macOS — экспериментальное направление

Официальный выпуск 1.0 предназначен для Windows x64. macOS-сборки CI остаются неподписанными и не считаются проверенным релизом.

## Возможности и ограничения

- Общий с Windows GUI на PySide6: импорт, анализ, конвертация видео в BD-ориентированный формат и подготовка структуры Blu-ray через tsMuxer.
- Отдельный безопасный **терминальный модуль записи готового ISO** — `macos_burn.py`, использует штатный `hdiutil burn`. В команде включены верификация записи и закрытие диска; параметрами отключается синтез файловой системы и изменение исходных блоков.
- **Не сделано:** запись из GUI одним нажатием, упаковка ISO с интерактивным меню через IMAPI (Windows), подтверждённая совместимость с плеерами, сертификация UDF 2.50, готовое приложение с цифровой подписью.
- **Важно:** размер и расширение ISO не доказывают соответствие Blu-ray/UDF 2.50. Сначала проверяйте на BD-RE и конкретном плеере.

## Mac с процессором Apple Silicon

1. Установите Python 3.11+ и FFmpeg (например, `brew install ffmpeg`).
2. Установите совместимый tsMuxer для macOS отдельно, указав абсолютный путь, если необходимо.
3. Выполните `bash start_macos.command` для GUI. Если бинарники Homebrew не видны из приложения, укажите их пути в настройках.
4. Привод ASUS BW-16D1HT — внутренний SATA 5.25\". Для подключения к Mac требуется **корпус или SATA–USB адаптер для 5.25\" оптических приводов с внешним питанием 12 В**. Переходника без питания недостаточно.
5. Запись из терминала (после создания ISO):

```bash
python3 macos_burn.py drives
python3 macos_burn.py check "/путь/к/фильму.iso" --profile BD25
python3 macos_burn.py burn "/путь/к/фильму.iso" --dry-run
python3 macos_burn.py burn "/путь/к/фильму.iso" --profile BD25 --device "ИДЕНТИФИКАТОР" --speed 2 --yes
```

### Контроль изменения ISO во время проверки

До проверки UDF/BDMV и после неё сравниваются идентификатор устройства,
inode, размер и времена изменения ISO. Непосредственно перед вызовом
`hdiutil burn` выполняется дополнительная проверка. Если ISO изменился,
удалён или заменён до запуска, запись блокируется. После завершения `hdiutil`
выполняется ещё одна проверка исходного отпечатка: даже при коде выхода 0
изменение ISO во время записи приводит к ошибке, а диск нельзя считать
проверенным. Такая проверка обнаруживает обычные изменения файловых метаданных,
но не заменяет побайтовую сверку уже записанного диска. Один и тот же
отпечаток, полученный до проверки UDF/BDMV, используется вплоть до запуска
команды записи: после возвращения из валидатора новый эталон не создаётся.
Команды `check` и `burn --dry-run` также сохраняют исходный отпечаток
до выдачи результата: они не сообщают об успешной проверке, если ISO
успел измениться после валидации, но до формирования команды.

Это защита от типичных ошибок параллельного редактирования, **не атомарный
снимок** и не гарантия целостности всего ISO: некоторые изменения содержимого
без изменения отслеживаемых метаданных могут остаться незамеченными. Проверка
после `hdiutil` не исправляет уже записанный диск. Не изменяйте ISO до
завершения записи; при ошибке проведите независимую проверку записанного диска.

## Дополнительная проверка BDMV внутри ISO (экспериментально)

Обычная проверка `check` оценивает метаданные UDF 2.50 и размер BD25/BD50,
но **не проверяет файлы BDMV**. На macOS доступен отдельный необязательный режим:

```bash
python3 macos_burn.py check "/путь/к/фильму.iso" --profile BD25 --inspect-bdmv
python3 macos_burn.py burn "/путь/к/фильму.iso" --dry-run --inspect-bdmv
python3 macos_burn.py burn "/путь/к/фильму.iso" --profile BD25 --device "ИДЕНТИФИКАТОР" --inspect-bdmv --yes
```

После успешной проверки метаданных UDF утилита монтирует ISO **только для чтения**
через `hdiutil attach -readonly -nobrowse`, запускает существующий статический
валидатор каталогов BDMV, MPLS, CLPI и M2TS, затем отключает проверочный
том через `hdiutil detach`. Привод и пустой диск для этого этапа **не нужны**.
Если монтирование, структурная проверка или отключение тома не удались,
запись **не начинается**. Принудительное отключение (`-force`) не применяется.

Опция намеренно **не включена по умолчанию**, пока не проведены испытания
реальных ISO на macOS; она не заменяет физическую проверку на ASUS BW-16D1HT
и бытовом Blu-ray-плеере. Даже положительный результат не доказывает
полную совместимость BD-J/HDMV меню или соответствие требованиям формата.
Обычный `--dry-run` не обращается к оптическому приводу; вместе с
`--inspect-bdmv` он временно монтирует ISO, но **не записывает носитель**.

Для **реальной записи через CLI** параметр `--device` обязателен: сначала выполните
`python3 macos_burn.py drives` и скопируйте точный идентификатор своего
привода. Без него `burn --yes` останавливается до проверки ISO и обращения
к оптическому устройству, чтобы `hdiutil` не выбрал другой привод автоматически.
Для `check` и `burn --dry-run` указывать привод необязательно. Это ограничение
CLI, а не утверждение о поддержке конкретной модели привода.

`check` выполняет локальную структурную проверку **метаданных UDF 2.50** без macOS и без привода. Реальная запись теперь автоматически останавливается до обращения к приводу, если образ не проходит такую проверку. Без `--profile` размер автоматически относит образ к BD25 или BD50; явный `--profile` блокирует образ, который не помещается на выбранный тип носителя. Проверка не анализирует всё дерево файлов UDF, BDMV/BD-J и воспроизводимость.

`--dry-run` не обращается к приводу, но выполняет проверку метаданных UDF 2.50, как при записи; повреждённый ISO отклоняется. Настоящая команда `burn` требует `--yes`, при этом macOS может дополнительно запросить вставить диск. В случае успеха утилита сообщает об успешной записи/проверке, но **это не подтверждает совместимость с бытовым плеером**.

## Сборка приложения

```bash
bash build_app_macos.sh
```

Результат: `dist/DiscForge-RU.app`. Это **неподписанная** сборка; выпуск подписанного/notarized приложения отдельный этап. В GitHub Actions настроена аналогичная экспериментальная сборка.

Windows и macOS используют общее ядро; интерфейс и BDMV-авторинг развиваются вместе. Аппаратные проверки macOS остаются в Roadmap.

### Восстановление после сбоя монтирования

Если `hdiutil attach` возвращает ошибку или превышает тайм-аут, программа проверяет, не остался ли образ частично смонтированным, и при необходимости пытается штатно отключить том. При ошибке `detach` проверка считается проваленной и запись **не начинается**. Принудительное отключение не применяется; содержимое смонтированного тома автоматически и рекурсивно **не удаляется**.

На macOS проверьте `hdiutil info` и вручную отключите оставшийся образ командой `hdiutil detach <устройство-или-точка-монтирования>` после закрытия использующих его программ. При повторной ошибке `detach` сначала выясните, какая программа удерживает том; не удаляйте вручную файлы BDMV на смонтированном носителе.
